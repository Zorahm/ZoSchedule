# Установка бота на VDS (Linux)

Пошаговая инструкция: чистый VDS → бот работает круглосуточно и сам поднимается
после перезагрузки. Примеры для Ubuntu 24.04 / Debian 12 (нужен Python 3.11+: в
Ubuntu 22.04 он 3.10, там придётся ставить новее отдельно).

Бот только **исходящий**: сам ходит на сайт колледжа и в Telegram, входящих
портов открывать не нужно. Часовой пояс сервера значения не имеет: бот везде
считает по Москве.

## 0. Что понадобится

- VDS: ориентир 1 ядро, 1 ГБ RAM (лучше 2 ГБ или 1 ГБ + swap, картинки рисует
  Chromium), 5 ГБ диска.
- Токен бота от @BotFather и группа, где бот будет администратором.
- SSH-доступ к серверу.

## 1. Где брать VDS: две сети должны быть доступны

С сервера должны открываться **оба** адреса:

| Что | Зачем |
|---|---|
| `api.telegram.org` | отправка картинок и сообщений |
| сайт колледжа (тот, что читает `parser.py`) | расписание |

Проверьте с будущего сервера до установки:

```bash
curl -sS -o /dev/null -w "telegram: %{http_code}\n" https://api.telegram.org
curl -sS -o /dev/null -w "college:  %{http_code}\n" -A "Mozilla/5.0" https://<адрес сайта колледжа>
```

Ответ любого HTTP-кода (даже 302 или 404) значит, что сеть есть. Таймаут или
сброс соединения значит, что адрес с этого сервера закрыт.

- **Telegram закрыт (бывает у российских хостеров):** возьмите прокси и задайте в
  `.env` `ZOSCHEDULE_BOT_PROXY=socks5://[логин:пароль@]хост:порт` (см. шаг 5).
  Прокси работает только для Telegram.
- **Сайт колледжа закрыт (бывает на зарубежных серверах):** бот этого обойти не
  умеет, возьмите сервер в России. Пока сайт недоступен, бот не падает: пишет в лог
  и постит по последнему успешному снимку.

## 2. Первичная настройка сервера

Под root, один раз:

```bash
adduser --disabled-password --gecos "" zos          # обычный пользователь для бота
usermod -aG sudo zos                                # нужен sudo: скрипт ставит службу
mkdir -p /home/zos/.ssh && cp ~/.ssh/authorized_keys /home/zos/.ssh/
chown -R zos:zos /home/zos/.ssh && chmod 700 /home/zos/.ssh

apt update && apt -y upgrade
apt -y install git python3 python3-venv python3-pip ufw

ufw allow OpenSSH && ufw --force enable             # входящий только SSH
```

Если у пользователя `zos` не будет пароля, а `sudo` без пароля не настроен,
задайте пароль: `passwd zos`. Скрипт установки вызывает `sudo` сам, только там, где
нужно.

Если RAM 1 ГБ, добавьте swap:

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo "/swapfile none swap sw 0 0" >> /etc/fstab
```

Дальше всё под пользователем `zos` (`ssh zos@сервер`). Запуск скриптов **от root
не нужен и не рекомендуется**: служба будет работать от того, кто ставил.

## 3. Получить код

Репозиторий приватный, поэтому серверу нужен доступ только на чтение. Самый простой
способ — deploy-ключ.

```bash
ssh-keygen -t ed25519 -f ~/.ssh/zoschedule_deploy -N "" -C "vds-zoschedule"
cat ~/.ssh/zoschedule_deploy.pub
```

Скопируйте вывод и добавьте на GitHub: репозиторий → **Settings → Deploy keys →
Add deploy key** (галочку «Allow write access» **не ставить**). Затем:

```bash
cat >> ~/.ssh/config <<'EOF'
Host github-zoschedule
    HostName github.com
    User git
    IdentityFile ~/.ssh/zoschedule_deploy
    IdentitiesOnly yes
EOF
chmod 600 ~/.ssh/config

git clone git@github-zoschedule:Zorahm/ZoSchedule.git
cd ZoSchedule
```

Другой вариант без ключей: скопировать проект с машины разработки, например
`rsync -a --exclude .venv --exclude '*.db' --exclude .env ./ zos@сервер:~/ZoSchedule/`.

## 4. Установка

```bash
chmod +x install.sh
./install.sh
```

Скрипт по шагам:

1. найдёт Python 3.11+, создаст `.venv` и поставит зависимости;
2. поставит Chromium для картинок (через Playwright, с системными библиотеками, по
   пути спросит пароль `sudo`);
3. спросит **токен** (ввод скрыт, токен проверяется в Telegram и пишется в `.env` с
   правами 600), **группу** (как на сайте колледжа) и время постов (Enter оставляет
   текущее значение);
4. создаст и запустит службу `zoschedule-bot` (автозапуск при загрузке, перезапуск
   при сбое через 10 секунд).

Если скрипт не смог проверить токен (Telegram закрыт с сервера), он предложит
«сохранить всё равно»: согласитесь и сразу переходите к шагу 5 с прокси.

## 5. Необязательно: прокси для Telegram

```bash
echo 'ZOSCHEDULE_BOT_PROXY=socks5://логин:пароль@хост:1080' >> .env
./install.sh restart
```

Поддерживаются `socks5://`, `socks4://`, `http://`, `https://`. В логе при запуске
появится строка «Telegram через прокси socks5://хост:1080» (логин и пароль туда не
попадают). Неверный формат бот отвергнет с подсказкой при запуске.

## 6. Подключить к группе

Бот слушается только **доверенных людей**. Сначала впишите их Telegram-id в `.env`
(числа, не ники; свой id покажет @userinfobot):

```bash
echo 'ZOSCHEDULE_BOT_TRUSTED_USERS=123456789,987654321' >> .env
./install.sh restart
```

Без этого `/go` не примет никто, а из любой группы, куда бота добавят, он выйдет
(предупреждение «trusted_users пуст» будет в журнале при запуске).

1. Добавьте бота в группу (это должен сделать доверенный человек, иначе бот сразу
   выйдет) и сделайте его **администратором** с правами «Удалять сообщения» и
   «Закреплять сообщения». Без них бот работает, но старое не удаляет и неделю не
   закрепляет.
2. Доверенный пользователь пишет в группе (в нужной теме, если группа с темами)
   команду **`/go`**. Бот запомнит чат, сразу пришлёт неделю и ближайший день,
   дальше всё идёт по расписанию: неделя по воскресеньям, «Сегодня» каждое утро,
   изменения текстом.

Остальным бот не отвечает вовсе, но пишет в журнал «Игнорирую /go от пользователя
<id>»: так можно узнать id нужного человека. Группа одна: `/go` доверенного в другой
группе переносит бота туда, прежнюю он не покидает сам. Группы, где бот уже был до
этой защиты, уберите вручную.

Проверка, что всё живо:

```bash
./install.sh status
./install.sh logs          # Ctrl+C — выйти
```

В журнале должны быть строки «Бот запущен…», «Бот слушает команды как @…» и
«Снимок обновлён ботом».

> **Одновременно запущен должен быть один бот на токен.** Если тот же токен
> работает ещё и на Windows (`start-bot.bat`) или на другом сервере, Telegram
> отвечает ошибкой 409 (конфликт), и апдейты делятся между ними случайно. Перед
> запуском на VDS остановите остальные.

## 7. Перенос с Windows с сохранением чата и учёта

По желанию, чтобы не писать `/go` заново и не потерять историю снимков. База хранит
снимки, чат и учёт отправленных сообщений.

1. На Windows остановите бота (Ctrl+C в окне `start-bot.bat`).
2. Скопируйте базу на сервер:
   ```bash
   scp backend/zoschedule.db zos@сервер:~/ZoSchedule/backend/
   ```
3. На сервере: `./install.sh restart`.

## 8. Повседневное

```bash
./install.sh status        # состояние службы
./install.sh logs          # журнал
./install.sh restart       # перезапуск
./install.sh token         # сменить токен и перезапустить
```

**Обновление бота:**

```bash
cd ~/ZoSchedule && git pull && ./install.sh </dev/null
```

`</dev/null` заставляет скрипт не задавать вопросов и оставить текущие токен, группу
и время. Он подтянет новые зависимости и перезапустит службу. База и `.env` под
`git pull` не попадают (в `.gitignore`).

**Сменить группу:** правьте `name` в `config.toml` **и заведите новую базу**,
иначе первый снимок новой группы сравнится со старой, и в чат уйдёт поток ложных
изменений:

```bash
sudo systemctl stop zoschedule-bot
mv backend/zoschedule.db backend/zoschedule-старая.db
./install.sh restart        # затем /go в группе
```

**Доверенные:** список `ZOSCHEDULE_BOT_TRUSTED_USERS` в `.env` (или `trusted_users` в
`config.toml`; `.env` приоритетнее). После правки `./install.sh restart`.

**Время постов:** `today_at` и `week_at` в `config.toml`, по Москве. Чтобы день
приходил накануне, включите `day_ahead = true`: в `today_at` уйдёт завтрашний день, а
сегодняшний провисит до конца пар.
После правки `./install.sh restart`.

## 9. Резервная копия

Всё важное: `backend/zoschedule.db` и `.env`. Копию базы безопасно делать, пока бот
работает:

```bash
cd ~/ZoSchedule
python3 - <<'PY'
import sqlite3
src = sqlite3.connect("backend/zoschedule.db")
dst = sqlite3.connect("/home/zos/zoschedule-backup.db")
src.backup(dst)
PY
```

Скачать: `scp zos@сервер:~/zoschedule-backup.db .`. Потерять базу не страшно (бот
соберёт новую и напишет `/go`), но вы потеряете историю снимков, из которой
считаются изменения.

## 10. Если что-то не так

| Симптом | Что делать |
|---|---|
| Служба не поднялась | `./install.sh logs`: последние строки журнала скажут причину. Чаще всего нет токена или Chromium не поставился |
| В логе 409 (Conflict) | тот же токен запущен ещё где-то; остановите второй экземпляр |
| Нет картинок, ошибки Chromium | `~/ZoSchedule/.venv/bin/python -m playwright install --with-deps chromium` (нужен sudo) |
| Бот молчит, в логе «Telegram недоступен» | Telegram закрыт с сервера: прокси (шаг 5) |
| В логе «Группа … не найдена среди N групп сайта» | это предупреждение, не ошибка: парсер идёт по имени. Чтобы обновить список, удалите `.groups_cache.json` |
| Расписание не обновляется | `logs` покажет ошибки парсера; сайт колледжа мог измениться или быть недоступен с сервера. Бот при этом постит по последнему снимку |
| Не удаляет сообщения о закрепе | у бота нет права «Удалять сообщения» |
| Пишет «message to edit not found» | кто-то удалил картинку в чате; бот сам забудет её и продолжит |

## 11. Удаление

```bash
./install.sh uninstall     # остановит и уберёт службу; каталог, .env и .venv остаются
```

# ZoSchedule — стандарты проекта

Telegram-бот расписания учебной группы МТИ: снимки расписания с сайта колледжа,
диффы между снимками, картинки недели и дня, тексты изменений. Ценность — в
изменениях: на сайте колледжа их не видно, они выводятся только сравнением
последовательных снимков.

## Раскладка

```
parser.py            парсер сайта — ВНЕШНИЙ КОНТРАКТ, не редактировать
config.toml          группа, интервал опроса, время постов
.env                 секреты (в git не попадает); шаблон — .env.example
backend/             Python + SQLite: парсер-обёртка, снимки, диффы
backend/app/bot/     Telegram-бот: картинки недели и дня, тексты изменений
```

## Незыблемое

**`parser.py` не редактируется.** Он читается как контракт: что отдаёт и в каком
виде. Всё, что нужно поправить в его выводе (нормализация `зачет`→`зачёт`, разбор
времени), живёт в `backend/app/parsing/`. Если сайт сломает
парсер — правится обёртка, парсер остаётся артефактом.

**Часовой пояс — Москва, жёстко.** `backend/app/moscow.py` — единственный
источник «сейчас». `datetime.now()` без tz в коде проекта запрещён. Все метки
времени — ISO со смещением.

**Снимки не апдейтятся поверх.** Каждый прогон парсера сохраняется целиком, с
меткой времени. Актуальное расписание — последний успешный снимок. Провалившийся
прогон тоже записывается (`status=failed`), чтобы было видно время попытки.

**Секреты не в репозитории.** Токен бота — `.env` или переменная окружения.

## Python

- Type hints везде, включая приватные функции и возврат `None`.
- `pyright --strict` без ошибок. `mypy --strict` тоже проходит.
- pydantic для всех внешних границ: конфиг, разбор сырья парсера.
- `pathlib`, не `os.path`.
- Диффы и работа со снимками — отдельные модули (`snapshots/`), SQL живёт только в
  `store.py`.
- Никаких голых `except Exception` без логирования и повторного возбуждения либо
  явного объяснения в комментарии, почему проглатываем.

## Общее

- Файлы ≤ ~300 строк. Функция помещается на экран.
- Комментарии объясняют «почему», а не «что». Комментарий, пересказывающий код
  словами, удаляется.
- Русский в пользовательских строках и комментариях, английский в идентификаторах.

## Поведение в отказах — часть контракта, не деталь реализации

| Ситуация | Поведение |
|---|---|
| Сайт колледжа недоступен, парсер упал, группа не найдена | Прогон записывается как `failed`, бот пишет в лог и продолжает по последнему успешному снимку. Никогда не молчит и не падает |
| Дата вне опубликованного диапазона | На картинке «Ещё не опубликовано». Это **не** «Выходной» |
| Дата внутри диапазона, пар нет (или стоит только пересдача) | «Выходной» |
| Преподаватель не указан | `null`, в картинках и текстах пишется «не указан на сайте». Строку не выбрасывать: пустое поле и отсутствие пары — разные вещи |
| Две пары в одном слоте | Обе в модели, обе на картинке. Не скрывать: скрытая пара неотличима от отменённой. Деления группы на подгруппы нет — поточная лекция это `stream`, не подгруппа |
| Telegram недоступен | Сообщения остаются в учёте бота и удаляются позже; задачи повторяются с паузой |

## Тесты

- Диффы — на подготовленных фикстурах снимков (`backend/tests/fixtures/`).
  Каждый вид события покрыт: `moved`, `cancelled`, `added`, `teacher_changed`.
- Бот — на поддельных Telegram и рендерере, база настоящая (временная). Время
  задаётся подменой `moscow.now`.
- Живых данных для разработки почти нет: летом сайт отдаёт по одной паре на
  группу. Всё, что сложнее одной пары, проверяется на синтетике.
